# Floor Planner — V1.0 开发记录与验收报告

> Web-based 2D Floor Planner，建造逻辑参考 **The Sims FreePlay**。
> 技术：纯 HTML / CSS / JavaScript（ES Modules）+ Canvas 2D，零依赖，`node server.mjs` 即可运行。

---

## 1. 如何运行

```bash
cd floor-planner
node server.mjs            # http://localhost:5173
npm test                   # 18 个几何 / 规则单元测试
npm run test:e2e           # 完整浏览器端到端测试（需 playwright + chromium）
```

无需 `npm install` 即可运行（无第三方运行时依赖）。项目结构：

```
floor-planner/
├── index.html
├── styles.css
├── server.mjs              # 无依赖静态服务器
├── src/

│   ├── store.js            # localStorage 持久化 + 内存回退

```

## 2. 关键决策：先取参考，再实现 L 型（规格书 §6.3）

规格书要求「先取得真实 FreePlay 参考截图，再实现 L 型几何逻辑」。这部分已完成，
证据与结论记录在 **`docs/REFERENCE.md`**，并附有原版截图（`docs/refs/`）。

从截图与官方提示文字中提炼出的机制：

| FreePlay 行为 | 截图依据 | 本项目实现 |
|---|---|---|
| 建造方式：按住拖动草地，绿色 = 可建，红色 = 不可建 | 面板 1 | 拖拽创建，绿色/红色实时预览 |
| 「Drag out a **yellow arrow anchor point** to extend a wall out」 | 面板 3 提示文字 | 每个矩形房间 4 角 × 2 个黄色锚点，共 8 个 |
| 延伸条带只有 **1 格厚**，紧贴被拖的那面墙 | 面板 3/4 与 7 | `renovatorExtend()`：footprint 扩张 k 格、挖去对角 k×(h-1) 或 k×(w-1) |
| 拖动时出现绿色勾 / 红色叉确认 | 面板 4 | 拖拽中实时校验，松手即提交（支持撤销） |
| 结果必须是 **一个完整房间**，不是两个房间拼接 | 面板 7 | 单一 room 对象 + `lshape/armW/armH` 数据模型 |
| 切回普通 Room 模式后，仍可拖动该段使其变宽 | 面板 6 + 任务 5 文字 | Select 模式下 L 型出现黄色菱形内角手柄 |
| 延伸缩短到 0 格 → 回到矩形 | 规格书 §6.2 | `normalizeShape()` 自动折叠；另有「Restore Rectangle」按钮 |
| 房间之间可以共用墙线，不能重叠 | — | 允许相邻，重叠被拒绝 |

**明确没有做的事（因为参考图不足以确认）**：
- 没有实现「U 型 / T 型 / 任意多边形」——永久设计规则只有矩形与 L。
- 没有允许对**已存在 L 型**再叠加第二个延伸（FreePlay 一个房间只有一个 L）。
- 没有实现 FreePlay 的「墙体内部相邻房间联动缩放」——规格书未列入 V1.0 范围。

## 3. 地块规格核实

规格书中的预设在开发前要求「最终核实游戏实际规格」，现已核实：

| 地块 | 规格书 | 游戏实际 | 结论 |
|---|---|---|---|
| Standard Lot | 18 × 18 | 18 × 18 | ✅ 一致 |
| Ocean View / Premium | 18 × 36 | 18 × 36 | ✅ 一致 |
| Penthouse | 12 × 26 | 26 × 12（宽 26 × 高 12） | ⚠️ 数值一致，横竖方向相反，已按规格书 12 宽 × 26 高实现 |

另外核实到一条与规格书 §5.2 完全吻合的官方规则：**游戏内最小房间是 1 × 2**，
不存在 1 × 1 房间——因此「只禁止 1 × 1」不是简化，而是还原原版规则。
（来源见 `docs/REFERENCE.md`）

> 如果之后希望把 Penthouse 改成 26 × 12，只需改 `src/geometry.js` 中
> `LOT_PRESETS.penthouse` 的两个数字即可，其余逻辑不受影响。

## 6. 数据模型

```json
{
  "app": "floor-planner",
  "format": 1,
  "exportedAt": "2026-10-30T04:00:00.000Z",
  "project": {
    "id": "proj_xxx",
    "name": "Kluang Family Home",
    "lot": "standard",
    "rooms": [
      { "id": "room_a", "name": "Living", "x": 1, "y": 1, "w": 7, "h": 6,
        "lshape": null, "armW": 0, "armH": 0 },
      { "id": "room_b", "name": "Kitchen", "x": 8, "y": 1, "w": 6, "h": 8,
        "lshape": "SW", "armW": 2, "armH": 3 }
    ]
  }
}
```

`lshape` = 被挖去的角（`NW | NE | SW | SE`），`armW` / `armH` = 缺口的宽与高（格）。
房间形状 = footprint 减去这一个角缺口，因此**在数据结构层面就不可能表达
矩形和 L 以外的形状**——永久设计原则由 schema 保证，而不只是靠 UI 限制。

## 7. 已知限制 / 后续建议

1. 浏览器本地存储受站点隔离，换浏览器或清缓存会丢失 → 请用 Export 备份（导入时会作为新项目落地，不会覆盖现有项目）。
2. 触屏：单指拖拽已可用（Pointer Events），双指捏合缩放未实现，建议 V1.1 补上。
3. 地块规格目前是常量表；若之后要开放自定义尺寸，需要先推翻「固定地块」原则。
4. 房间暂无用途标签（卧室 / 厨房等），可作为 V1.1 的小增量，不影响几何逻辑。
